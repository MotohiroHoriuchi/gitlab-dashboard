Field guide / 操作マニュアル

「遅れてる？」を、
迷わず確かめる。

起動から絞り込み、4つのビューの使い分け、会議での見せ方まで。日々よく使う操作を画面付きで説明します。

対象バージョン 1.2.0 既定URL http://localhost:48273 データ更新 60秒ごと

01 / GET STARTED

まず画面を開く

動作確認だけなら GitLab の認証情報は不要です。実データで使うときは、先に管理者が接続設定を済ませます。

TRY WITH SAMPLE DATA

サンプルデータで試す

4つのビューと遅延表示をすぐ確認できます。

npm install
MOCK_GITLAB=1 npm run dev
USE YOUR GITLAB DATA

実データで使う

.env.local に接続先、プロジェクト、トークンを設定して起動します。

cp .env.example .env.local
npm run dev
  1. ターミナルで起動します。「Ready」と表示されたら準備完了です。
  2. ブラウザで http://localhost:48273 を開きます。
  3. 画面上部のプロジェクト名と最終更新時刻を確認します。別プロジェクト名や古い時刻なら、操作前に接続設定を確認します。

データは自動更新されます。 画面は60秒ごとに再取得します。GitLabで変更した直後は、最大約60秒待ってから確認してください。

02 / ORIENTATION

4つのビュー

上部の4つのボタンが入口です。迷ったら、知りたいことに合わせて選びます。

イシュー一覧

どの仕事が長引いているかを確認。日々のトリアージの最初に使います。

Close日数の分布

何が、誰が時間を使っているかを比較。月次やスプリントの振り返り向けです。

カレンダー

いつからいつまで、どれが遅れているかを確認。直近2週間の調整に向きます。

ロードマップ

マイルストーンが期限までに終わりそうかを確認。目標単位の進捗共有に使います。

03 / FILTER

見たい範囲だけに絞り込む

状態・ラベル・担当者・マイルストーンの選択は、イシュー一覧とカレンダーで共通です。選択後の件数は右端の「該当」で確認できます。

Open ラベル 2 担当者 1 マイルストーン ▾ 該当 4件 / 全34件
  1. 状態を選びます。 未完了だけなら「Open」、完了分だけなら「Closed」、両方なら「すべて」です。
  2. 「ラベル」「担当者」「マイルストーン」を押します。 候補が多いときは、先頭の検索欄に名前の一部を入力します。
  3. 候補を複数選択できます。 ボタンに表示される数字が選択中の件数です。
  4. 解除するときはポップアップ下部の「選択をクリア」を押します。
選び方判定例
同じ項目内で複数選択いずれかに一致ラベル「bug」「urgent」→どちらかを持つイシュー
項目をまたいで選択すべてに一致Open ＋ 担当者「田中」→田中さんの未完了イシュー
何も選ばないその項目では絞らない担当者が未選択→全担当者

Close日数の分布はフィルタの影響を受けません。 分布ビューでは、右上の「ラベル／担当者／マイルストーン」で集計の切り口を変えます。

04 / TRIAGE

長引いている仕事を探す

イシュー一覧は、滞留日数を横棒で並べます。斜線のバーはOpen、単色のバーはClosedです。

  1. 「イシュー一覧」を開きます。
  2. 未解決の詰まりを探すなら「Open」→「長引き順」。 上から確認すれば、滞留が長い順に見られます。
  3. バー左側でラベル・タイトル・担当者・マイルストーンを確認します。
  4. 対象を狭めたいときはラベルや担当者を追加します。 右端の該当件数が想定どおりか確認します。
  • 緑
    30日未満
  • 黄
    30日超
  • 赤
    90日超
  • 斜線
    Open（未解決）

見る順番のおすすめ：「最長滞留（Open）」→一覧先頭のタイトル→担当者・マイルストーン。長期化の理由や次のアクションはGitLabのイシューで確認します。

05 / RETROSPECTIVE

時間のかかり方を比べる

Close済みイシューの所要日数を、ラベル・担当者・マイルストーン単位で比較します。中央値が大きい順に並びます。

  1. 「Close日数の分布」を開きます。
  2. 右上で「ラベル」「担当者」「マイルストーン」のいずれかを選びます。
  3. 気になる行にマウスを重ねます。 下部に件数、未解決、最小、中央値、最大などが表示されます。
  4. 中央値だけでなく件数も確認します。 1〜2件のグループは箱ではなく個々の点で表示されるため、傾向判断には注意します。
表示読み方
箱中央50%のイシューが収まる範囲（Q1〜Q3）
箱の中の縦線中央値。代表的な所要日数を見るときの基準
ひげ一般的なばらつきの範囲
点外れ値、または件数が少ないグループの各データ

06 / SCHEDULE

遅れと直近の予定を確認する

カレンダーは、マイルストーンとイシューを同じ時間軸に並べます。赤い斜線が、予定日を過ぎた期間です。

基本操作

CALENDAR CONTROLS
  1. 「2週」または「月」を選びます。 2週は日々の調整、月は俯瞰に向きます。
  2. 「‹」「今日」「›」で期間を移動します。 迷ったら「今日」で現在の期間に戻ります。
  3. バーにマウスを重ねます。 #ID、担当者、ラベル、期間、期限、予実差分を確認できます。
  4. バーをクリックします。 所属マイルストーンや関係するイシューが強調され、ほかが薄くなります。もう一度押すか、外側を押すと解除します。
  5. 「+N件」を押します。 その日の全予定が開きます。項目を選ぶと、カレンダー上の関係を強調できます。

赤い斜線と予定線の読み方

状態画面表示意味
期限内に完了完了イシューの単色バー予定日までにClose
遅れて完了予定日以降が赤い斜線予定日からClose日までが超過
期限超過・進行中予定日以降、今日まで赤い斜線まだOpenで予定日を超過
期限なし・進行中赤い斜線なし予実差分は判定できない

表示曜日とチェックポイント

  • 凡例右側の「月〜日」チップを押すと、その曜日を表示／非表示にできます。既定では土日が非表示です。
  • 曜日設定はブラウザに保存され、次回も引き継がれます。
  • 凡例の「★ チェックポイント」を押すと、重要な予定だけが一時的に強調されます。

07 / MILESTONE

目標までの残作業を追う

ロードマップは1マイルストーンを1行で表示します。左側で完了率と残数、右側で期間と未完了イシューの期限を見ます。

  1. 「ロードマップ」を開きます。 状態フィルタはありません。進捗計算にOpenとClosedの両方が必要なためです。
  2. 左側の完了率・残数・超過件数を確認します。 スパークの実線は残数、破線は理想的な減り方です。
  3. 右側で本日線と期限の位置を比べます。 赤いtickは期限超過、★はチェックポイントです。
  4. 行をクリックします。 大きなバーンダウンと「超過／今週／それ以降」の残作業一覧が展開します。
  5. もう一度行を押すか Esc で閉じます。 「+N」を押した一覧は、外側クリックでも閉じられます。

日程が表示されない場合： GitLabのマイルストーンに開始日または期限を設定してください。日付がないマイルストーンは、時間軸上のバーを描けません。

08 / PRESENT

会議用の全画面表示

カレンダーとロードマップには全画面モードがあります。ヘッダーやほかの指標を隠し、フィルタと現在のビューだけを画面いっぱいに表示します。

朝会で詰まりを確認

  1. イシュー一覧
  2. Open → 長引き順
  3. 上位3件の次アクションを確認

週次で遅れを確認

  1. カレンダー → 2週
  2. 期限超過（進行中）を確認
  3. 全画面で担当者・予定を共有

振り返りで傾向を比較

  1. Close日数の分布
  2. ラベル→担当者の順に切替
  3. 中央値と件数を記録

計画会議で残作業を確認

  1. ロードマップ
  2. 対象マイルストーンに絞る
  3. 行を開き、超過／今週を確認

Esc の解除順： ポップアップ → 選択中の強調 → 展開中の行 → 全画面。重なっている場合は必要な回数だけ押してください。

09 / DATA HYGIENE

GitLab側の情報を整える

ダッシュボードの見え方は、GitLabのイシューとマイルストーンの入力内容で決まります。表示がおかしいときは、まず元データを確認します。

GitLabで設定する項目ダッシュボードでの使われ方運用の目安
イシューのタイトル一覧、カレンダー、ロードマップの表示名作業内容が一目で分かる短い名称
担当者担当者フィルタ、分布、詳細表示着手前に割り当てる
ラベルラベルフィルタ、分布、代表ラベル、チェックポイントチーム内の分類を揃える
期限（due date）予定線、遅延判定、未完了tick遅れを見たい作業には必ず設定
マイルストーンフィルタ、所属関係、ロードマップ目標単位で紐づける
マイルストーンの開始日・期限カレンダー／ロードマップの期間バー両方を設定すると最も読みやすい
イシューのClose完了日、Close日数、納期遵守率完了した日にCloseする
複数ラベルがあるイシューの扱い

絞り込みとチェックポイント判定は全ラベルを見ます。一覧のラベルチップと「ラベル別」分布では、GitLabが返す配列の先頭ラベルを代表として表示します。

開始日がないイシューの扱い

カレンダーでは、イシューの開始日に created_at を使います。終了は、完了済みなら closed_at、未完了で期限があれば due_date、期限もなければ今日です。

チェックポイントにする方法

既定では checkpoint ラベルを付けたイシューが★になります。ラベル名を変える場合は、起動環境の CHECKPOINT_LABEL を変更します。

10 / TROUBLESHOOTING

困ったとき

よくある症状から、最初に確認する場所をまとめています。

「データを取得できませんでした」と表示される
  1. .env.local の GITLAB_BASE_URL、GITLAB_PROJECT_ID、GITLAB_TOKEN を確認します。
  2. トークンに read_api スコープがあるか確認します。
  3. GitLabのURLへサーバーから接続できるか、トークンの期限が切れていないか確認します。
GitLabで変更したのに画面へ反映されない

自動更新とサーバーキャッシュはともに60秒です。1分ほど待ち、ブラウザのタブを一度切り替えて戻るか、ページを再読み込みします。

探しているイシューが表示されない

状態、ラベル、担当者、マイルストーンの選択数を確認し、それぞれのポップアップから「選択をクリア」します。カレンダーでは表示期間と非表示曜日も確認してください。

カレンダーに遅延の斜線が出ない

遅延判定にはイシューの期限が必要です。GitLabで due date を設定してください。期限のない未完了イシューは、今日までのバーは表示されますが遅延とは判定されません。

ロードマップにマイルストーンが出ない／バーがない

マイルストーンフィルタを解除し、GitLab側で開始日・期限を設定します。イシューが0件でも取得済みマイルストーンは選択できますが、日程がなければ時間軸バーは描けません。

設定やDockerでの起動方法も知りたい

環境変数の全一覧、Docker、アーキテクチャ、テスト方法は README を参照してください。
